# 疑似アラーム情報 データ仕様書

## 1. 概要

本仕様書は、監視装置の試験で使用する疑似アラーム情報データの形式を定義する。
データは JSON 形式で記述し、複数のアラーム情報を配列として保持する。

- **用途**: 監視装置の試験用（疑似アラームデータの投入・検証）
- **形式**: JSON
- **文字コード**: UTF-8

## 2. 全体構造

ルートオブジェクトは `alarms` キーを持ち、その値はアラームオブジェクトの配列である。

```json
{
  "alarms": [
    { /* アラームオブジェクト */ },
    { /* アラームオブジェクト */ }
  ]
}
```

| キー | 型 | 必須 | 説明 |
|---|---|:---:|---|
| `alarms` | 配列 | ○ | アラームオブジェクトの一覧 |

## 3. アラームオブジェクト

1件のアラーム情報を表すオブジェクト。

| フィールド | 型 | 必須 | 説明 | 例 |
|---|---|:---:|---|---|
| `alarmId` | 文字列 | ○ | アラームを一意に識別するID | `ALM-00001` |
| `alarmName` | 文字列 | ○ | アラームの名称 | `温度異常` |
| `alarmLevel` | 数値（整数） | ○ | アラームの重大度（1〜3） | `3` |
| `targetDeviceId` | 文字列 | ○ | アラーム対象となる装置の名前（NOIMの装置名 `commonName`。入力CSVのノード名 `name` と同じ） | `関西・アバンザCER1-A` |
| `occurredAt` | 文字列 | ○ | アラーム発生日時（ISO 8601形式） | `2026-11-05T09:12:30+09:00` |
| `status` | 文字列 | ○ | アラームの状態 | `active` |

## 4. 各フィールドの詳細

### 4.1 alarmId
- アラームを一意に識別する文字列。
- 推奨形式: `ALM-` + 5桁の連番（例: `ALM-00001`）。
- 重複は不可。

### 4.2 alarmName
- アラームの内容を表す名称。
- 日本語の記述を可とする（例: `温度異常`、`通信断`）。

### 4.3 alarmLevel
- アラームの重大度を表す整数値。**1〜3 の3段階**。
- 数値が大きいほど重大度が高い。

| 値 | 区分 | 説明 |
|:---:|---|---|
| `1` | 軽度 | 最も軽い。情報レベルの通知 |
| `2` | 中度 | 注意が必要な状態 |
| `3` | 重度 | 最も重い。重大な異常 |

### 4.4 targetDeviceId
- アラームの対象となる装置の名前を入れる文字列。NOIM形式の装置（PD）の `commonName`（入力CSVのノード名 `name`）と**完全一致**で突き合わせる。
- 例: `関西・アバンザCER1-A`、`関西・COM京都南RR2-A`、`アバンザSAS2-01-A_アバンザCER1-A01`。
- 同一装置で複数のアラームが発生する場合、同じ値が複数レコードに現れてよい。
- 装置名に一致しない値は、可視化ツールで「対応する装置のないアラーム」として一覧表示される。

### 4.5 occurredAt
- アラームが発生した日時。
- 形式: ISO 8601（タイムゾーンオフセット付き）。
- 例: `2026-11-05T09:12:30+09:00`（日本時間 JST）。

### 4.6 status
- アラームの現在の状態を表す文字列。以下のいずれかの値をとる。

| 値 | 説明 |
|---|---|
| `active` | 発生中（未復旧） |
| `recovered` | 復旧済み |

## 5. データ例

```json
{
  "alarms": [
    {
      "alarmId": "ALM-00001",
      "alarmName": "温度異常",
      "alarmLevel": 3,
      "targetDeviceId": "関西・アバンザCER1-A",
      "occurredAt": "2026-11-05T09:12:30+09:00",
      "status": "active"
    },
    {
      "alarmId": "ALM-00002",
      "alarmName": "通信断",
      "alarmLevel": 2,
      "targetDeviceId": "関西・COM京都南RR2-A",
      "occurredAt": "2026-11-05T09:45:10+09:00",
      "status": "active"
    },
    {
      "alarmId": "ALM-00003",
      "alarmName": "電源電圧低下",
      "alarmLevel": 1,
      "targetDeviceId": "アバンザSAS2-01-A_アバンザCER1-A01",
      "occurredAt": "2026-11-05T08:30:00+09:00",
      "status": "active"
    },
    {
      "alarmId": "ALM-00004",
      "alarmName": "ファン回転数低下",
      "alarmLevel": 2,
      "targetDeviceId": "関西・アバンザCER1-A",
      "occurredAt": "2026-11-05T10:05:47+09:00",
      "status": "recovered"
    },
    {
      "alarmId": "ALM-00005",
      "alarmName": "電源電圧低下",
      "alarmLevel": 1,
      "targetDeviceId": "関西・谷町ビルCER1-B",
      "occurredAt": "2026-11-05T07:50:00+09:00",
      "status": "recovered"
    }
  ]
}
```

## 6. 制約・備考

- 全フィールドは必須とする。
- `alarmLevel` は 1〜3 の整数のみを許容する。
- `status` は `active` / `recovered` のいずれかのみを許容する。
- `occurredAt` は ISO 8601 形式に従うこと。
- サンプルデータは `alarm_sample.json` を参照。
